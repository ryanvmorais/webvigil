# 015 — Web toolchain modernization — design

## Overview of the approach

Three upgrades, applied as separate stages so each can be verified on its own
before the next starts, then landed together:

1. **Node 20 → 24.** Pure plumbing: CI matrix value, the `web/` Docker base
   image, an `engines` floor, and `@types/node`. No source changes. Done first
   because it is the cheapest and de-risks the other two (both frameworks want a
   current Node).
2. **Tailwind CSS 3 → 4.** The largest surface: a new PostCSS plugin, a rewrite
   of the `globals.css` entry and theme into the v4 CSS-first form, the removal
   of `tailwind.config.ts`, an `animate` plugin swap, and a syntax pass over the
   11 `components/ui/*` files. `tailwind-merge` 3 rides along here.
3. **Next.js 15 → 16.** Smaller than it looks: the dashboard is 100% client
   components (`"use client"` everywhere, `useParams`/`useSearchParams` from
   `next/navigation`), so none of the Next 15→16 async-request-API breaking
   changes apply. The real work is the removal of `next lint` and the
   `eslint-config-next` 16 wiring.

Each stage ends at the `web/` quality gate. The whole spec is complete when CI is
green and the four Dependabot PRs are retired.

The dashboard is not redesigned. Every token keeps its value; every route
renders the same. The e2e Playwright flow is the automated proof of that.

## Components

### Stage 1 — Node 24

- **CI.** `.github/workflows/ci.yml` `web` job: `node-version: "24"`. The
  `quality` job (Python) and `docker` job are untouched. While here, remove the
  `version: 9` input from `pnpm/action-setup@v6` — the action reads
  `packageManager: pnpm@9.15.4` from `web/package.json`, and keeping both is a
  latent conflict (from the PR #6 review).
- **Docker.** `web/Dockerfile`: `FROM node:24-alpine` in the `deps`, `build`
  and `runner` stages. `corepack enable` stays. The non-root `nextjs:nodejs`
  user, `EXPOSE 3000`, and the standalone `CMD ["node", "server.js"]` are
  unchanged (RNF-05).
- **`engines`.** Add to `web/package.json`:
  ```json
  "engines": { "node": ">=24" }
  ```
  `.npmrc` keeps `strict-peer-dependencies=false`; no `engine-strict` is added,
  so a mismatched Node is a warning, not a hard failure (open question 5).
- **`@types/node`.** Pin to `^24` (matching the runtime), not the `26.x` that
  Dependabot PR #8 proposes. `@types/node` majors track Node majors; `26.x`
  would type against APIs Node 24 does not ship. PR #8 is closed as superseded.

### Stage 2 — Tailwind CSS v4

- **Packages.** Remove `tailwindcss@^3`; add `tailwindcss@^4` and
  `@tailwindcss/postcss@^4` (both dev). Remove `tailwindcss-animate`; add
  `tw-animate-css` (dev). `postcss` stays. `prettier-plugin-tailwindcss` stays
  (0.6.x reads v4).
- **PostCSS.** `web/postcss.config.mjs`:
  ```js
  const config = { plugins: { "@tailwindcss/postcss": {} } };
  ```
- **`globals.css` rewrite.** Structure, in order:
  1. `@import "tailwindcss";` — the single v4 entry, replacing the three
     `@tailwind` directives.
  2. `@import "tw-animate-css";` — the `animate-in` / `fade-*` / `zoom-*` /
     `slide-*` utilities the dialog, dropdown and select components use.
  3. `@custom-variant` — none. Dark mode is `prefers-color-scheme` only
     (spec 003 RF-02 / ADR-8); v4's built-in `dark:` variant already keys off
     the media query and the app does not use `dark:` utilities anyway.
  4. `:root { … }` — the bare-channel token triples, values byte-identical to
     today (`--background: 0 0% 100%;` …), plus `--radius` and the
     `--severity-*` scale.
  5. `@media (prefers-color-scheme: dark) { :root { … } }` — the dark overrides,
     values byte-identical to today.
  6. `@theme inline { … }` — maps the tokens into Tailwind's namespace so the
     utilities resolve:
     ```css
     --color-background: hsl(var(--background));
     --color-foreground: hsl(var(--foreground));
     --color-primary: hsl(var(--primary));
     --color-primary-foreground: hsl(var(--primary-foreground));
     /* … border, input, ring, secondary, muted, accent, popover, card, destructive … */
     --color-severity-info: hsl(var(--severity-info));
     --color-severity-low: hsl(var(--severity-low));
     --color-severity-medium: hsl(var(--severity-medium));
     --color-severity-high: hsl(var(--severity-high));
     --color-severity-critical: hsl(var(--severity-critical));
     --radius-lg: var(--radius);
     --radius-md: calc(var(--radius) - 2px);
     --radius-sm: calc(var(--radius) - 4px);
     ```
     `inline` is required so the generated utilities emit `hsl(var(--token))` at
     the use site — that is what lets the `prefers-color-scheme` block override
     them.
  7. `@utility container { … }` — v4 drops the configurable `container`
     component; replace the old `theme.container` (`center: true`,
     `padding: 1.5rem`, `screens.2xl: 1200px`) with:
     ```css
     @utility container {
       margin-inline: auto;
       padding-inline: 1.5rem;
       @media (width >= 1200px) { max-width: 1200px; }
     }
     ```
     `app-shell.tsx` uses `className="container"` in three places; this keeps
     them identical.
  8. `@keyframes accordion-down` / `accordion-up` + the `--animate-accordion-*`
     theme entries — moved here from the deleted config (Radix accordion isn't
     currently mounted, but the tokens are cheap to keep and match shadcn).
  9. `@layer base { * { @apply border-border; } body { … } }` — unchanged in
     intent; `@apply` works in the entry file. The system font stack stays.
- **`tailwind.config.ts` deleted.** `content`/`safelist` are automatic in v4
  (it scans the project). `darkMode` is not needed. `components.json`
  `tailwind.config` becomes `""`.
- **`components/ui/*` syntax pass.** v4 changed the shorthand for "use this CSS
  variable as the value" from `[--x]` to `(--x)`. Affected classes seen in the
  tree: `origin-[--radix-dropdown-menu-content-transform-origin]`,
  `origin-[--radix-select-content-transform-origin]`,
  `max-h-[--radix-select-content-available-height]`,
  `min-w-[8rem]` (stays — literal value, not a var). Hand-edit the 11 files,
  then run `pnpm dlx shadcn@latest diff` (or a fresh `shadcn add` into a temp
  dir) as a cross-check that nothing else drifted (open question 4).
- **`tailwind-merge` 3.** Bump; `cn` unchanged. The badge / findings-table /
  status-filter component tests exercise `cn` conflict resolution and are the
  regression check (RF-05).

### Stage 3 — Next.js 16

- **Upgrade.** Run `pnpm dlx @next/codemod@canary upgrade latest` — bumps
  `next`, `eslint-config-next`, `react`, `react-dom`, `@types/react*` within the
  `^19` range and applies any mechanical codemods. Review the diff; the app
  being all-client means the async-`params` / `cookies()` / `headers()` codemods
  should be no-ops here.
- **`next lint` removal.** Next 16 removes the command. `pnpm lint` changes from
  `next lint` to `eslint`. `eslint.config.mjs` is reconciled:
  - keep the `ignores` block (`.next`, `coverage`, `playwright-report`,
    `test-results`, `.playwright-tmp`, `src/lib/api-types.ts`, `next-env.d.ts`);
  - keep the rule set: `next/core-web-vitals`, `next/typescript`, then
    `prettier` **last**;
  - drop `FlatCompat` / `@eslint/eslintrc` **only if** `eslint-config-next` 16
    exports a flat config directly; otherwise keep the compat shim.
  - `next.config.ts` keeps `eslint: { ignoreDuringBuilds: true }` (the gate
    lints explicitly; `next build` should not re-lint).
- **Turbopack.** Next 16 defaults `next build` to Turbopack (ADR-4). Keep the
  default. The two things to verify because they are baked at build time in this
  project: `output: "standalone"` still emits `server.js` for the Docker image
  (RNF-05 / RF-09), and `rewrites()` still proxies `/api/*` (spec 003 RNF-06).
  If either breaks under Turbopack, set the build script to `next build
  --webpack` and record it; `next dev` stays on Turbopack regardless.
- **e2e.** `playwright.config.ts` rebuilds the UI with the e2e API port before
  `next start` (`pnpm exec next build && pnpm exec next start`). No config change
  expected; the suite passing is RF-09's proof.

## Interfaces

No API or URL contract changes. The only "interface" touched is the build
pipeline:

- **PostCSS input:** `@tailwindcss/postcss` consumes `globals.css`; output is
  the same utility CSS the components already reference.
- **ESLint entry:** `pnpm lint` → `eslint` reading `eslint.config.mjs` (flat).
- **Docker build arg:** `web/Dockerfile` still takes `API_PROXY_TARGET` and sets
  `NEXT_OUTPUT_STANDALONE=1` (unchanged).

## ADRs

### ADR-1 — Node 24, not Node 22

**Decision.** Target Node 24 (Active LTS) for CI, the `web/` image, and the
`engines` floor.

**Alternatives.** (a) Node 22 (Maintenance LTS). (b) Node 24 (Active LTS).

**Why.** Node 20 is already end-of-life; the point of the move is to be current
and stay current. Node 24 is in Active LTS until late 2026 and Maintenance until
2028, versus Node 22 which is already in Maintenance. Local dev is on Node 24
(`v24.15.0`), CI runners default to Node 24, and Dependabot PR #8's intent is a
forward move.

**Trade-off.** A newer runtime has a marginally higher chance of a native-module
or tooling edge case than the older LTS. Mitigated by the fact that the `web/`
dependency tree is pure JS/TS with no native addons, and CI builds the image on
every PR.

### ADR-2 — Tailwind v4 CSS-first, no `tailwind.config.ts`

**Decision.** Configure Tailwind entirely in `globals.css` via `@theme inline`
and `@utility`; delete `tailwind.config.ts`; keep the existing bare-channel HSL
token values unchanged.

**Alternatives.** (a) Keep `tailwind.config.ts`, bridged with `@config` — the
minimal-diff path. (b) Full CSS-first.

**Why.** CSS-first is the v4 default and the shadcn v4 convention; a lingering
JS config is a second source of truth that Dependabot keeps bumping and that
future shadcn updates assume away. Keeping the `:root` token *values* exactly as
they are (only moving where the theme *mapping* lives) means light and dark
render byte-identically (RF-04).

**Trade-off.** A larger diff in `globals.css` and a one-time syntax-learning
cost. Accepted — it is a single file and the result is less config overall.

### ADR-3 — `tw-animate-css` replaces `tailwindcss-animate`

**Decision.** Swap `tailwindcss-animate` (unmaintained, v3-only, a JS plugin)
for `tw-animate-css` (v4-native, imported from CSS).

**Alternatives.** (a) `tw-animate-css`. (b) Drop the dependency and inline the
`animate-in` / `fade-*` / `zoom-*` / `slide-*` keyframes actually used by the
dialog, dropdown and select components.

**Why.** `tw-animate-css` is the successor shadcn itself moved to, so the
`components/ui/*` files stay regenerable from the shadcn CLI. Inlining would
fork them from upstream for no real gain.

**Trade-off.** One more third-party dependency instead of ~30 lines of local
CSS. Accepted for the regenerability.

### ADR-4 — Adopt Turbopack for `next build`

**Decision.** Use the Next 16 default (Turbopack) for `pnpm build`; fall back to
`next build --webpack` only if the standalone output or the baked `rewrites()`
misbehave.

**Alternatives.** (a) Opt out to webpack immediately for parity with the current
build. (b) Adopt the default.

**Why.** Turbopack builds are stable in Next 16 and are the maintained path
forward; opting out pre-emptively just defers the same migration. The two
project-specific risks (standalone `server.js`, build-time `rewrites()`) are
both covered by existing gates — the Docker build and the e2e suite — so a
regression is caught immediately.

**Trade-off.** Slightly less battle-tested than webpack for the standalone
edge cases. Bounded by the fallback, which is a one-line change.

### ADR-5 — Next 16 is low-risk here because the app is all client components

**Decision.** Treat the Next 15→16 upgrade as a tooling change, not an
architecture migration.

**Context.** The Next 15→16 breaking changes centre on the Dynamic APIs
(`params`, `searchParams`, `cookies()`, `headers()` becoming async) and caching
semantics. This dashboard renders entirely client-side: every route is
`"use client"`, routing state comes from `useParams`/`useSearchParams`
(`next/navigation` hooks, already sync-on-client), and there are no server
components reading request data, no `middleware.ts`, no `next/image`, no
`next/font`.

**Consequences.** The codemod pass should be close to a no-op in `src/`. The
review focus is the build (Turbopack, standalone) and the lint wiring, not the
route code.

### ADR-6 — Hand-migrate `components/ui/*`, cross-check with the shadcn CLI

**Decision.** Edit the 11 `components/ui/*.tsx` files by hand for the v4 syntax,
then diff against a fresh shadcn CLI generation as a check.

**Alternatives.** (a) Regenerate all 11 from `shadcn add` at v4. (b)
Hand-migrate + CLI diff.

**Why.** The files carry local docstring and formatting conventions
(`/estilo-arquivos`); a blind regenerate would revert those and could pull
unrelated upstream changes. The only mechanical change needed is the
`[--x]` → `(--x)` arbitrary-variable syntax. The CLI diff catches anything
missed.

**Trade-off.** Manual effort and the risk of missing a class. Mitigated by the
CLI cross-check and by `pnpm build` failing loudly on an unresolved utility.

### ADR-7 — Browser-support floor moves with Tailwind v4

**Decision.** Accept Tailwind v4's raised baseline (Safari 16.4+, Chrome 111+,
Firefox 128+).

**Why.** v4's engine uses native cascade layers, `@property`, and
`color-mix()`. WebVigil's dashboard is a developer-facing local tool, not a
public site; its users run current browsers. There is no analytics or
compatibility requirement in spec 003 that this violates.

**Trade-off.** The dashboard would render incorrectly on a 3+-year-old browser.
Accepted for this audience.

## Impact on existing code

- **`web/tailwind.config.ts` is deleted.** Anything importing `Config` from it —
  nothing does; it is only read by the Tailwind CLI and `components.json`.
- **`globals.css` is substantially rewritten** but every token value is
  preserved. This is the highest-review-attention file in the spec.
- **`components/ui/*` (11 files)** get a mechanical syntax edit. shadcn-owned
  files, normally not hand-edited — noted in the task list so a future
  `/estilo-arquivos` pass knows why they diverge from a bare CLI generation.
- **`eslint.config.mjs`** changes shape; the *effective* rule set does not.
- **`.github/workflows/ci.yml`** — one value plus one input removal in the `web`
  job. The `quality` and `docker` jobs are untouched.
- **`web/Dockerfile`** — base image tag only.
- **Requirements RF-01 correction:** the root `Dockerfile` and
  `docker/target.Dockerfile` are Python 3.12 images and are **not** touched;
  only `web/Dockerfile` uses Node.
- **Docs:** `docs/web-ui.md` (Node version, config-file mention), `CLAUDE.md`
  (stack line, spec-status paragraph), `specs/README.md` (roadmap row). `README`
  names no toolchain version today, so likely no change.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| A `components/ui/*` class silently stops resolving under v4 | Medium | `pnpm build` errors on unknown utilities; shadcn CLI diff; the a11y + component test suite renders every UI primitive |
| Turbopack build breaks `output: "standalone"` or baked `rewrites()` | Low–Medium | Covered by the `docker build ./web` job and the e2e suite; fallback is `next build --webpack` (ADR-4) |
| A visual regression the e2e flow does not cover (checks page, settings, empty/error states) | Low | Manual pass over those routes once, listed as a task |
| `eslint-config-next` 16 flat-config wiring differs from expectation | Medium | Task allows keeping `FlatCompat`; lint output (zero warnings) is the gate |
| `@next/codemod` touches route code unexpectedly | Low | Diff is reviewed task-by-task; all-client architecture (ADR-5) makes async-API codemods no-ops |
| Bundle size grows beyond RNF-03's ~10% | Low | `pnpm build` route table captured before/after and compared |

## Test strategy

No new test files. The spec rides the existing gates, run at the end of each
stage and once more all together:

- **Unit (`pnpm test`, vitest, 86 tests).** The component tests
  (`badges.test.tsx`, `findings-table.test.tsx`, `status-filter.test.tsx`,
  `a11y.test.tsx` rendering every page) are the Tailwind-v4 and `tailwind-merge`-3
  regression backstop.
- **Types (`pnpm typecheck`).** Catches `@types/node` / `@types/react` drift and
  any Next 16 type change.
- **Lint (`pnpm lint`) + format (`pnpm format:check`).** The new ESLint CLI must
  report zero warnings; `prettier-plugin-tailwindcss` must sort v4 classes
  cleanly.
- **Build (`pnpm build`).** Fails on any unresolved utility or Next 16
  incompatibility. Capture the route/size table for RNF-03.
- **e2e (`pnpm test:e2e`, Playwright, offline).** Setup → login → real scan →
  report → logout against the real API + engine. This is the no-visual-
  regression and RF-09 proof. Must stay fully offline (RNF-02).
- **Docker (`docker build ./web`).** The Node 24 base and the standalone output.
- **Root `docker` job.** Unchanged, must stay green (sanity that nothing
  cross-cutting broke).

Manual, once: view `/checks`, `/settings`, and the empty/error states of
`/scans` and `/scans/[id]` in a browser after the migration (RNF-01).
